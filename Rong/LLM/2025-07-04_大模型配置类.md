# 配置类（Config Class）

​		配置类是一个理解大模型很好的切入点，它就像是模型的“蓝图”或者“说明书”，用一种清晰、集中的方式定义了模型的所有可配置参数

## 定义配置类

```python
from transformers import PretrainedConfig

class MyLLMConfig(PretrainedConfig):
    model_type = "myllm"
```

​		一般来说，普遍做法是让自己的配置类继承自 Hugging Face 的 `tranformers` 库的 `PretrainedConfig`。这样的好处是模型能够自动兼容 Hugging Face 生态系统中的各种工具，比如 `from_pretrained()` 和 `save_pretrained()` 方法，可以简化模型的加载、保存和分享。 

## \_\_init\_\_方法

```python
def __init__ (
    self, 									# 这个参数没什么好解释的，就是类对象本身
    # 训练与正则化（Training & Regularization）
    dropout: float = 0.0,					# 在训练过程中随机丢弃神经元的比率，防止过拟合
    hidden_act: str = 'silu',				# 使用的激活函数，例如 "silu" 或 "gelu"
    rms_norm_eps: float = 1e-05,			# RMSNorm 层的超参数，用于在计算中防止除以零
    # 核心架构参数
    hidden_size: int = 512; 				# 模型中嵌入层和隐藏层的大小，最核心的尺寸参数
    num_hidden_layers: int = 8,				# Tranformer 层的数量，决定了模型的深度
    num_attention_heads: int = 8,			# 多头注意力机制中“头”的数量
    intermediate_size: int = None,			# 前馈网阔（FFN）中间层的维度
    max_position_embeddings: int = 32768,	# 模型能够处理的最长序列长度
    # 词汇表与特殊
    vocab_size: int = 6400,					# 词汇表的大小
    bos_token_id: int = 1,					# 句子开始的特殊标记的ID
    eos_token_id: int = 2,					# 句子结束的特殊标记的ID
    # 注意力机制细节
    num_key_value_heads: int = 2,			# 用于分组查询注意力(GQA)的键/值头的数量
    flash_attn: bool  = True,				# 是否使用 Flash Attention，一个更高效的注意力算法实现
    rope_theta:	int = 1000000.0,			# 旋转位置编码(RoPE)的参数
    ################################################################################
    # 关于 MoE 模块的配置，如果 use_moe 为 False，以下的参数都是无效的
    # 若想了解更多细节，请查看模型架构笔记
    ################################################################################
    use_moe: bool = False,					# 一个布尔开关，决定是否启动 MoE 模块
    num_experts_per_tok: int = 2,			# 每个 toekn 选择的专家数量
    n_routed_experts: int = 4,				# 总的专家数量
    n_shared_experts: int = 1,				# 定义了共享专家的数量
    scoring_func: str = 'softmax',			# 指定门控网络用来计算每个专家得分的函数
    aux_loss_alpha: float = 0.1,			# 辅助损失(Auxiliary Loss)的 alpha 系数
    seq_aux: bool = True,					# 是否在序列级别上计算辅助损失
    norm_topk_prob: bool = True,			# 是否标准化 top-k 概率
    **kwargs								# 用于捕获未显式定义的关键字参数，为了保证兼容性 
):
    super().__init__(**kwargs)				# 将 myllm 不支持但 PretrainedConfig 支持的参数交给父类的初始化函数去处理		
    # 以下就是赋值，就不写了，格式如下：
    self.dropout = dropout
    ...
    self.norm_topk_prob = norm_topk_prob
```

​		总结下来，一个优秀的大模型配置类有如下特点：

- 集中化：所有超参数都集中在一个地方，便于查找和修改
- 标准化：通过继承 `PretrainedConfig` 等基类，与主流框架和生态保持一致
- 可读性强：参数命名清晰，并按逻辑分组，让人一目了然
- 灵活性高：可以方便的通过添加新的参数来支持新的模型变体
