# 预训练

## 名词辨析

1、`epoch`：一个 epoch 指的是整个训练数据集被完整的过一遍，所以 `epoch` 指的是训练的总轮数

2、`batch`：在训练一个模型时，我们通常不会一次性把整个数据集都输入到模型中，GPU 的显存不支持；一次只用一个样本来更新模型，训练会过慢，且梯度更新很不稳定。所以把整个数据集分为很多个小的、大小相等的数据块， 每一个数据块就叫做 `batch`

3、`batch_size`：一个 `batch` 中有多少个样本，就是 `batch_size`。比如 32 表示一个 batch 中包含 32 个句子

4、`accumulation_steps`：梯度累计步数，模型处理一个 batch 后不会立即更新梯度，而是继续计算第二个 batch，把计算好的梯度累加到前一步的梯度上，重复 `accumulation_steps` 后，模型再用累计起来的总梯度去更新一次权重。

5、**Effective Batch Size**：等效批次大小，等于 $batch\_size*accumulation\_steps$，使用更大的批次大小通常能让训练过程更稳定

## 预训练过程

​		模型一个 `Batch` 一个 `Batch` 地处理数据。然而在处理可变长序列时（如文本）时，为了将它们组成一个整齐的矩阵张量进行计算，我们必须让批次内的所有序列长度一样。通常的做法就是以批次中最长的序列为基准，用一个特殊的”填充词元“（padding token）来补齐所有较短的序列。

*示例：*”我爱机器学习“，”深度学习“，”自然语言处理很有意思”

处理后变为：["我", "爱", "机", "器", "学", "习", "\<pad\>", "\<pad\>", "\<pad\>", "\<pad\>"]

​					["深", "度", "学", "习", "\<pad\>", "\<pad\>", "\<pad\>", "\<pad\>", "\<pad\>", "\<pad\>"]

​					["自", "然", "语", "言", "处", "理", "很", "有", "意", "思"]

​		这样操作带来的问题就是，模型在预测这些 `<pad>` 位置的下一个词元时，也会计算出一个损失值。但是，这些 `<pad>` 词元并不包含任何语义信息。让模型去学习如何预测填充词元，是在浪费模型的学习能力，并且会引入无意义的梯度信号，干扰训练过程。

### loss_mask

​		`loss_mask` 就是为了解决这个问题而生的。它是一个和我们的目标序列形状完全相同的张量，但它的值只有 0 和 1。

- 对于**有效词元** （真实的词，非填充词）的位置， `loss_mask` 在对应位置的值是 1 。
- 对于**填充词元** （ `<pad>` ）的位置， `loss_mask` 在对应位置的值是 0 。

​		就相当于一个掩码，一般来说在读取数据时，每读取一条数据就会自动生成该条数据的 `loss_mask`，一个 `batch` 的 `loss_mask` 就是一个多维张量

```python
loss = (loss * loss_mask).sum() / loss_mask.sum()
```

1、先计算批次中每一个位置的损失，得到一个损失张量（`initial_loss` ）这个张量在填充位和非填充位都有损失值

2、将这个损失张量与 `loss_mask` **逐元素相乘**，就能保留非填充位的损失值

3、将相乘后的结果张量中所有值累加得到 `(loss * loss_mask).sum()`

4、对 `loss_mask` 本身求和，得到有效次元的数量 `loss_mask.sum()`

5、两者相除，就能得到每个词元的平均损失
