# Agent

​		简单来说，Agent是一种能够自主地观察、思考、行动和做出决策的智能体。它与 LLM 的区别主要在，LLM 只有一个大脑，通过输入文本获得输出文本。但是 Agent 通过代码加强，能够识别大脑规划的指令，并调用各种工具，来完成复杂的任务。

一般来说，一个 Agent 应该至少具有以下几个能力：

1、**思考与规划**：能够像人一样，把一个大问题拆解为一系列可执行的小步骤

2、**行动**：能够调用工具执行之前规划的步骤

3、**记忆**：能够记住之前的行动和结果，并利用这些信息来指导后续的决策

## 思考与规划

​		对于 Agent 来说，思考和规划是智能的体现，其实说白了，就是通过提示词工程，使得 LLM 能够理解当下任务场景，以及接下来该怎么做

## 行动

​		对于 Agent 来说，其实就是理解工具是什么，理解工具的用处，最后学会使用工具。

### Function Calling

​		首先各个厂商为了让 LLM 在对话中能够调用外部函数/工具，都给 LLM 了一种能力，即将自然语言请求转换为结构化函数调用，执行后返回结果。具体实现其实说白了，也是通过提示词工程，要求大模型给出格式化的输出——函数名和参数

示例如下：

````
# 提示词前部分xxxxxxx
# 可用工具：
- compare_two_float： 比较两个浮点数的大小
	- num1: 第一个浮点数
	- num2: 第二个浮点数
- get_weather_of_city: 获取某个城市的天气
	- city: 要获取天气的城市名 
# 输出格式要求：请你根据用户问题，判断是否需要调用工具。如果需要，请按照如下格式给出需要调用的工具名和参数：
```json
{
	"function_name": "工具名",
	"parameters": [
		{"name": "参数1名", "value": "参数1的值"},
		...
	]
}
```
````

### MCP

​		MCP 是一个听起来很高端的词汇，如果去搜索定义，其定义也是比较的复杂。其实本质上来说，MCP 就是 Anthropic[^1] 为了实现 AI工具调用大一统，提出来的协议。没错，就是上面提到的 `Function Calling`，由于各个厂商对于 Function Calling 给出的格式不同，导致很麻烦，就像充电器界的 type-c 接口逐步统一一样，MCP 也是为了将这些结构化的工具调用消息格式进行统一。

所以总结下来，`Function Calling` 与 `MCP` 的关系，其实就是：MCP 可视为 Function Calling 的标准化实现形式

## 记忆

​		目前基本上大部分 LLM 都是无状态的计算，其实就是，对于 LLM 的计算来说，每一次发过来的 token sequence 都和上一次的完全没有关系，示范如下：

```python
# 第一轮
user = "0.9和0.11哪个数更大？"
reply = "因为11大于9，所以0.11大于0.9"
# 第二轮
user = "你在鬼扯，小数点前面数字的比较和小数点后面数字的比较是不同的！"
reply = "您说的对，小数点前面数字的比较就是和小数点后面数字的比较是不同的。如果您有具体的例子需要讨论，我可以帮您分析。"
```

​		但是有些人就会好奇了，那为什么在和豆包、千问聊天的时候，他们能知道前面说的东西呢？其实关键就在于每次发送的 token ！

### 消息

​		我们暂且这么规定，为了区分每一轮对话的时候，你发送的问题与 LLM 给出的回答，我们设定一个 `role` 也就是角色的字段，如果是你发送的问题，则该字段为 `user`；如果是大模型的回答，则该字段为 `assistant`。别问为什么这么起名字，问就是王八的屁股——规定。然后内容统一用 `content` 字段存储，这样在 python 中就可以很方便的存储每次的对话了对吧：

```python
[
    {"role": "user", "content": "0.9和0.11哪个数更大？"},
    {"role": "assistant", "content": "因为11大于9，所以0.11大于0.9"},
]
```

​		为什么我们需要存储对话呢，就是为了让大模型实现记忆。我们的直觉中，每次向 LLM 发起问话时，我们只是发送了新的问题，大模型根据这个问题做出解答。但是实际上，在每个会话中，也就是这个玩意：

![./images/新会话.png](./images/新会话.png)

​		我们都会保存一个叫做 `messages` 的变量，每一次我们提出的问题和 LLM 给出的结果，都会添加到这个列表中，然后**每次发送的都是 `messages` 这个变量！**也就是说由于每次大模型接收的 token 中包含了之前的问题和回答，大模型才能知道之前的信息。下面是示范：

```python
# 第一轮
user = "0.9和0.11哪个数更大？"
# messages = [
# 	{"role": "user", "content": "0.9和0.11哪个数更大？"}
# ]
reply = "因为11大于9，所以0.11大于0.9"
# messages = [
# 	  {"role": "user", "content": "0.9和0.11哪个数更大？"}
#     {"role": "assistant", "content": "因为11大于9，所以0.11大于0.9"},
# ]
# 第二轮
user = "你在鬼扯，小数点前面数字的比较和小数点后面数字的比较是不同的！"
# messages = [
#     {"role": "user", "content": "0.9和0.11哪个数更大？"},
#     {"role": "assistant", "content": "因为11大于9，所以0.11大于0.9"},
#     {"role": "user", "content": "你在鬼扯，小数点前面数字的比较和小数点后面数字的比较是不同的！"}
# ]
reply = "对不起，之前由于我的失误，给了你错误的答案。实际上，小数点后面数字的比较应该从小数点后逐位比较，所以0.9比0.11大"
# messages = [
#     {"role": "user", "content": "0.9和0.11哪个数更大？"},
#     {"role": "assistant", "content": "因为11大于9，所以0.11大于0.9"},
#     {"role": "user", "content": "你在鬼扯，小数点前面数字的比较和小数点后面数字的比较是不同的！"},
#     {"role": "assistant", "content": "对不起，由于我的失误，给了你错误的答案。实际上，小数点后面数字的比较应该从小数点后逐位比较，所以0.9比0.11大"}
# ]
```

所以实际上，总结下来，大模型的记忆就是指这里的 `messages`，你想让 LLM 记住什么，那就把信息加到 messags 变量中去，这样 LLM 就能知道该信息。
