# 大模型的训练

​		大模型的训练流程通常分为三个阶段：

- 预训练：在海量无标注数据上训练模型（学习语言统计规律）
- 监督微调：用高质量标注数据调整模型行为
- 强化学习微调（可选）：进一步通过人类反馈优化输出

## 低秩自适应（Low-Rank Adaptation, LoRA）

​		一种用于高效微调大模型的技术，核心思想是通过低秩矩阵[^1]分解大幅减少训练参数量，从而在保持性能的同时显著降低计算成本和显存需求

​		传统微调需要更新整个模型的权重，计算开销极大，存储多个任务专用模型的副本成本高昂。实际上在微调大模型时，预训练模型已经捕获了大量知识，微调时只需要调整少量关键方向，因此权重矩阵 $W$ 的更新量 $\Delta W$ 通常具有<font color="red">**低秩特性**</font>。

### 1、训练流程

​		（1）选择目标层：通常为 `Transformer` 的注意力矩阵（Q/K/V）或全连接层

​		（2）初始化适配器：$A$ 用随机高斯分布初始化，$B$ 初始化为零矩阵（为了保持初始时$\Delta W=0$）

​		（3）前向传播：

​				- 原始输出：$h = Wx$

​				- `LoRA` 调整后输出：$h=Wx+\alpha\cdot BAx$

​				<font color="honydew">注：不同任务的适配器是独立的 $(B_i, A_i)$ 对，需单独管理</font>

​		（4）反向传播：仅计算 $A$ 和 $B$ 的梯度，冻结其他参数

​		（5）推理合并：将 $W+BA$ 合并为单一矩阵，无需额外计算开销

### 2、关键参数与调优

- 秩（Rank）$r$：权衡表现力和效率，通常 4~64 （越大越接近全微调，但计算量增加）
- 适配器位置：注意力层（Q/K/V）效果最佳，FFN 层次之
- 缩放系数：对 $BA$ 乘系数 $\alpha$（类似学习率），需要与 $\gamma$ 协调（如 $\alpha/\gamma$ 固定）

### 3、优势

​		训练参数仅占 0.1% ~ 1%，显存占用极低，接近全参数微调效果

​		冻结预训练模型的主干网络（参数固定），仅通过动态加载/卸载轻量级的 `LoRA` 适配器（Adapter）来适应不同任务

### 4、局限性

1、低秩假设未必普适：极端复杂任务可能需要更高秩适配

2、适配器位置敏感：需实验确定最佳插入层

3、动态秩选择：固定秩可能限制灵活性（后续研究提出动态调整秩）

[^1]: **低秩矩阵（Low-Rank Matrix）**是线性代数中的一个重要概念，指**可以被分解为两个或多个更小矩阵乘积的矩阵**。若矩阵大小为 `(m, n)` 的矩阵 *M*，其秩 `r ≪ min⁡(m, n)`，则称 *M* 为低秩矩阵。这种矩阵具有显著的冗余性和压缩潜力。

# 数据集

## 监督微调（Supervised Fine-Tuning, SFT）数据集

​		在预训练模型的基础上，通过监督学习对模型进行任务特定的微调，核心目标是：

- 对齐模型行为：让模型的输出更符合人类意图或特定任务需求
- 提升可控性：通过标注数据明确指导模型“应该怎么回答”，而非仅依赖预训练时的统计模式

​		**SFT数据集**是用于监督微调的标注数据，其核心特点是：

- **输入-输出对**：每个样本包含一个输入（如用户指令）和对应的**理想输出**（由人类或专家提供）。
- **高质量、小规模**：相比预训练数据（TB级），SFT数据通常较小（万到百万级样本），但质量要求极高。

#### **常见SFT数据集示例**

| 数据类型 | 输入示例                                    | 输出示例                                                     |
| :------- | :------------------------------------------ | :----------------------------------------------------------- |
| 指令遵循 | "写一首关于春天的诗"                        | "春风拂面百花开，柳絮轻扬燕归来…"                            |
| 问答对   | "地球半径是多少？"                          | "平均半径约6371公里。"                                       |
| 多轮对话 | 用户："推荐一部科幻电影" AI："《星际穿越》" | 用户："为什么推荐它？" AI："因为它的科学细节严谨且情感深刻。" |

## 基于人类反馈的强化学习（Reinforcement Learning from Human Feedback，RLHF）数据集

​		RLHF数据集不直接提供“标准答案”，而是通过**人类对模型输出的排序或评分**来间接指导模型学习更符合人类价值观的响应

- **不是输入-输出对**，而是**同一输入对应的多个模型输出+人类排序/评分**。
  **示例**（文本生成任务）：
  - **输入（Prompt）**: "解释相对论的基本概念"
  - **输出A（模型生成）**: "相对论是爱因斯坦提出的，分为狭义和广义。"
  - **输出B（模型生成）**: "相对论描述了时空和引力的关系，E=mc²是著名公式。"
  - **人类标注**: 输出B ≻ 输出A（B优于A）

​		一般来说比 `SFT` 数据集更小，但是成本极高。通常会与 `SFT` 结合，`SFT` 提供基础任务能力（“学会回答”），`RLHF` 优化回答质量（“回答的更好”）

## 推理（Reason）数据集

​		是一类专门设计用于提升模型逻辑推理、分布思考和复杂问题解决能力的高质量数据，核心目标是让模型学会像人类一样逐步分析问题，而不仅仅是依赖模式匹配或记忆。

<font color="honedew">**注：`Reason` 数据集属于监督微调（SFT）阶段的子集，专门针对逻辑推理能力进行强化**</font>

**Reason数据集**包含需要多步推理才能解决的问题，通常具有以下特点：

- **输入-输出对**：问题 + **详细推理过程**（而不仅是最终答案）。
- **任务类型**：数学证明、逻辑谜题、常识推理、编程算法等。
- **结构要求**：答案需展示清晰的中间步骤（如“因为…所以…”）。

**示例**（数学推理）：

- **输入**: "若x + 3 = 7，且y = 2x，求y的值。"

- **输出**:

  ```text
  步骤1: 解方程x + 3 = 7 → x = 7 - 3 = 4。  
  步骤2: 计算y = 2x → y = 2 * 4 = 8。  
  最终答案: y = 8  
  ```

​		`Reason` 数据集的核心价值是解决大模型的“跳跃推理”问题，就是直接输出答案，`Reason` 数据集强制模型显式生成推理链；通过分布学习，模型能处理未见过的复杂问题；并使得模型决策更透明，便于人类验证

​		实际应用中，Reason数据常与SFT、RLHF结合：**SFT**教会模型“回答问题”；**Reason数据**教会模型“如何思考”；**RLHF**确保推理结果符合人类偏好。
