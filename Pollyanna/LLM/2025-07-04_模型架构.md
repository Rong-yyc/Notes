# 模型架构

​		我们从输入到输出捋一遍 MiniMind 的模型结构。在 MiniMind 中使用了现代深度学习模型设计的一个核心理念：即将核心的模型骨架（Model Backbone）与具体的任务头（Task Head）分开。

​		模型骨架是模型的主体部分，代码中是 `MiniMindModel`，好比是汽车的发动机和底盘，这部分非常强大和通用，但是本身并不能直接完成特定的任务。`MiniMindModel` 的工作是接受输入的 `token`，经过多层 `Transformer Block` 的复杂设计，最终输出一系列高维度的向量，这些向量就是对输入文本的深度理解和特征提取。

​		任务头是一个附加在模型骨架之上的、通常比较浅的网络层，代码中是 `MiniMindForCausaLLM.lm_head`。好比是在同一个汽车底盘和发动机上，可以安装不同的车身。装上轿车车身，就能载客；装上卡车车斗，就能运货。它接受模型骨架输出的通用特征，并将其”翻译“为特定任务所需要的最终输出。

​		这样的设计模式是”迁移学习“思想的体现，最大好处是**模块化**和**可重用性**，也是 `Hugging Face Transformers` 库的基石。我们可以花费巨大的计算资源预训练一个强大的模型骨架，然后应用于不同的下游任务，只需要在其上面接上一个轻量级的、针对特定任务的任务头，就可以用于文本分类、命名实体识别、问答等多种任务。而我们只需要对这个小小的任务头进行微调。

## 词元编码器（Tokenizer Encoder）

​		众所周知，计算机只能计算数字，所以我们首先得想办法将输入的文本转换为对应的数字

<font color="red">注：从这里开始输入的形状都是指训练时的一个 batch 中的一条训练数据，训练时是一个 batch 训练的</font>

- 输入：在大模型中，输入通常是可变长度的文本序列
- 输出：一串 token 序列（长度由分词结果决定）

​		我们挑选一个分词器计算得到的词汇表，大小为 `vocab_size`，是一个将 token 映射到整数 ID 的映射表

<font color="honydew">**注：词汇表的大小为超参数 `vocab_size`，在训练分词器的时候指定，所以实际上词元编码器还不属于大模型结构**</font>

​		词元编码器就是将输入根据词汇表进行分词，变成一个个的 `token`，这样输入就会变成一串 `n` 个 `token` 序列

[^1]: 对于中文来说，这里的 `token` 中包含的汉字个数从 1 到多个不等，所以给出一个输入，最终得到的 token 序列长度取决于分词结果。例如“机器学习”可能会被分为 ["机器", "学习"] 或 ["机", "器", "学", "习"]

## 输入嵌入（Input Embedding）

​		这一层主要是将 token 表示为向量

- 输入：一串长度为 `n` 的 token 序列
- 输出：一个形状为 `(n * d_model)` 的输入嵌入矩阵

<font color="honydew">**注：每个token对应的向量维度为超参数 `d_model`，在训练大模型的时候指定**</font>

​		在这里该层是通过**查表**实现的，在大模型中会初始化一个 `(vocab_size x d_model)` 大小的嵌入矩阵[^2]，这样对于词汇表中的每个 token，都能在表中找到对应的 `d_model` 维度的向量。

​		在模型训练的过程中，这个嵌入矩阵也会不断更新。通过大量数据的反向传播，语义相似的 token 会逐渐在向量空间中靠近，反之则会远离。

[^2]: 注意，预训练模型的嵌入矩阵是训练后的结果，已经包含了语义信息，直接加载使用即可。

## Transformer层（Transformer Layer）

​		如果说嵌入矩阵像”字典“的话，`Transformer层` 就像是”理解句子的脑细胞“。Transformer 层的自注意力机制会动态调整表示，如”苹果“在”吃苹果“和”苹果手机”中的向量不同。

- 输入：形状为 `(n * d_model)` 的输入嵌入（Input Embedding）
- 输出：形状为 `(n * d_model)` 的 `hidden_states`

​		这里主要概括一下：`hidden_states` 不是一个简单的矩阵，而是包含了极其丰富信息的高维语义表示。对于序列中的每一个 Token（比如“我”、“爱”、“吃”），它对应的 `d_model` 维向量都是该 Token 在完整上下文中的表示。也就是说，“爱”的向量不仅包含了“爱”本身的含义，还融合了“我”和“吃”对它的影响。

​		我觉得 Transformer 层值得单独开一个笔记，所以详细解释见 [Transformer层详细解析](./2025-07-04_Transformer层.md)

## 归一化层（Normalization Layer）

​		归一化层是深度学习中常见的组件，主要是为了稳定训练过程，通过对神经网络的下一层的输入进行归一化，来解决**内部协变量偏移（Internal Covariate Shift）**[^3]的问题。常见的归一化层类型如下：

- 批归一化（Batch Normalization, BN）
- 层归一化（Layer Normalization, LN）
- 实例归一化（Instance Normalization, IN）
- 组归一化（Group Normalization, GN）

### 层归一化（LayerNorm）

​		标准的 `LayerNorm` 不仅会用标准差对数据进行缩放，还会减去均值来中心化数据。此外，`LayerNorm` 有两个可学习参数：一个缩放参数 $\gamma$，和一个偏移参数 $\beta$

- 输入：Transformer 层的输出
- 输出：归一化后的数据，形状不变

### 均方根归一化（Root Mean Square, RMSNorm）

​		这是一种简化版的层归一化，`RMSNorm` 只通过 `RMS` 对输入进行缩放，而不进行中心化。只有一个缩放参数，没有偏移参数，这种简化使得 `RMSNorm` 在计算上比 `LayerNorm` 更快，同时在很多 Transformer 模型中被证明非常有效，甚至效果更好。

```python
class RMSNorm(torch.nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
		"""
		输入：
            dim: 输入张量的最后一维的大小，即特征维度。
            eps: 一个小的浮点数，用于防止除零错误。默认值为 1e-5。
        输出：
            None
		"""
        super.__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))
	
    def _norm(self, x):
    	"""
    	实现归一化计算的核心
    	1、首先计算输入 x 中每个元素的平方 x.pow(2)
    	2、沿着最后一个维度(特征维度)计算均值, 这就是均方(Mean Square) .mean(-1, keepdim=True)
    	3、加上一个极小值 eps 防止开方根时分母为零 + self.eps
    	4、计算上一步结果的平方根的倒数(Reciprocal Square Root) 这等价于 1 / sqrt(...) ，但计算上更高效 torch.rsqrt(...)
    	5、将原始输入乘以这个平方根的倒数, 就完成了归一化
        """    
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
   	
    def forward(self, x):
        """
        这是前向传播的完整过程
        1、首先调用 _norm() 函数对输入进行归一化, 这里先进行了类型转换以保证计算精度
        2、将计算结构的数据类型转换为原始输入的类型
        3、将归一化后的结果与可学习的 weight 参数相乘，进行缩放
        """
        return self.weight * self._norm(x.float()).type_as(x)
```

​		`self.weight` 是 `RMSNorm` 中唯一的可学习参数，是一个与输入维度相同的向量，初始化为全 1。这个参数允许模型在归一化之后，对每个特征维度进行缩放，学习不同特征的重要性。

​		实际上具体的公式也不用记，只需要知道有这么一种简化版的层归一化就好了

[^3]: 首先内部协变量是指神经网络中某一层的输入数据分布，是统计学概念，如输入数据的均值、方差等。在训练过程中，由于参数不断更新，前一层的输出会动态变化，导致后一层的输入分布持续改变。这就是内部协变量偏移问题

## 线性层（Linear）

​		这里的线性层实际上在类 `MiniModelForCausaLLM` 中实现。该类通过在 `MiniMindModel` 上添加一个任务头，将一个通用的 Transformer 模型特化为一个可以进行文本生成的语言模型。

```python
self.lm_head = nn.Linear(self.config.hidden_size, self.config.vocab_size, bias=False)
```

​		这是最关键的一步。它创建一个任务头，这个任务头的任务是“因果语言建模”（Causal Language Modeling）。这个层的任务是预测下一个单词，通过将 `MiniMindModel` 输出的最终隐藏状态向量，投影到整个词汇表的大小。这样，输出的每个维度就对应了词汇表中一个词的分数（logits），分数越高的词，就越有可能是下一个要生成的词。

- 输入：归一化后的 Transformer 层的输出，形状为 `(n * d_model)`
- 输出：下一个词的 logits（其实只是一组未经归一化的分数，可正可负，数值范围不固定）

## Softmax 层

​		其实在模型架构里并不包含这一层，这一层是隐藏在训练脚本中。上一层我们拿到的结果，在预训练脚本中拿给了 `loss_fct`，也就是一个实例化后的 `nn.CrossEntropyLoss` 层去计算损失函数。该层内部隐式地包含  `Softmax` 操作。

- 输入：下一个词的 logits，形状为 `(1 * vocab_size)`
- 输出：一个概率列表，形状为 `(1 * vocab_size)`

​		Softmax 函数将这一组分数转换为一个概率分布，其中所有词的概率都在 0 到 1 之间，且所有词的概率值加在一起等于 1。我们就能知道词汇表中每一个 token 是下一个 token 的可能性有多大

## 词元解码器

​		众所周知，人类聊天用的是文本，所以我们首先得想办法将输出的概率转换为对应的 token

- 输入：一个概率列表，包含词汇表中所有词元的概率，形状为 `(1 * vocab_size)`
- 输出：下一个 token

​		现在我们有了每个词的概率，但到底应该选哪个词呢？这里有多种策略，成为解码策略/采样策略。最简单的就是总是选择概率最高的那个词，这种方法速度快，但是容易生成重复、无趣甚至不连贯的文本。具体的相关介绍，我也觉得应该开一个单独的笔记记载，现在这篇已经太长了，详情见 [解码策略/采样策略](./2025-07-04_解码策略.md)

# 循环往复

​		一旦选定了下一个词，这个词的 tokenID 就会作为新的输入，送回模型，然后重复上面的过程。直到模型生成了一个特殊的“终止符”（`EOS`）或者达到了预设的最大长度。因为继承了 Hugging Face 的`GenerationMixin` ，我们只需要调用 `.generate()` 方法，并通过参数来指定使用哪种策略，Hugging Face 库会为我们处理好这一切。

## Q&A

1、一旦选定了下一个词，这个词就会作为新的输入。比如我输入“我爱吃”，先预测“下一个词”，选了“饭”，下一轮的输入只是“饭”？这样计算不就变成串行的了？

答：在 生成文本（推理） 时，大模型确实是 一个 Token 一个 Token 地向外“吐”的。这个过程被称为自回归，因为模型的每一步输出都会作为下一步的输入。这个过程在逻辑上是串行的。但是下一轮的输入并不是“饭”，而是“我爱吃饭”，模型需要完整的上下文才能准确预测下一个词

2、如果每一轮都要把越来越长的完整序列重新计算一遍，那么效率不是太低了么？

答：如果真的这么做，效率会非常低下。为了解决这个问题，几乎所有现代的 Transformer 模型都采用了一种叫做 KV Cache（键值缓存） 的技术。也就是说，Transformer 就是用来解决这个问题的，去看另一篇笔记把 [Transformer层](../2025-07-04_Transformer层.md)
